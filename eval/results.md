# Scam-script rules: evaluation

Generated by `python eval/run_rules_eval.py` on `eval/transcripts.jsonl`: 48 calls, 24 scam and 24 ordinary.

**What this is:** short call transcripts written for this test (with AI assistance), modelled on scam patterns that the FTC, the FBI and Indian police describe, and on ordinary calls that share their words (a real bank's fraud check, a delivery driver, a friend asking for $20). **What it isn't:** recordings of real calls. It tests the rules on clean text; on a live call Whisper's mistakes come first.

## Results

| Threshold | Scam calls caught (recall) | Ordinary calls flagged (false alarms) | Precision |
| --- | ---: | ---: | ---: |
| Live alert, script ≥ 80 | 6/24 (25%) | 0/24 (0%) | 100% |
| Some scam signs, ≥ 40: Protected Send holds for a callback | 21/24 (88%) | 0/24 (0%) | 100% |

**Reading it:** the live alert is deliberately strict, so most scams in this set land between 40 and 79 (“some scam signs”) rather than setting off the red banner. That is why the payment gate doesn't wait for the alert: any payment made on a call scoring 40 or more is held until the user calls the person back on a saved number (`gate_level` in `app/feature/payment_gate.py`).

## What this doesn't show

- The transcripts were written for the test, not taken from real calls, and the rules were tuned on similar phrasing, so real-world recall will be lower.
- Live calls add speech-recognition errors (Hindi on phone audio especially; see README §5).
- The local LLM layer, which adds flags the phrases miss, isn't part of this test.
- The voice model is measured separately: `eval/voice_eval.py`, on recordings.
